## 自动化测试

从源码根目录运行：

```bash
python3 -m unittest discover -v
```

此前的离线基线包含 **61 项测试**，使用 `unittest` 和确定性的 Codex 协议夹具。夹具运行在独立进程中，不调用真实模型，也不实际执行其模拟的编程命令。覆盖内容包括：

- MCP stdio 消息格式、初始化、发现、参数校验、结构化结果及版本协商。
- MCP 适配器、私有后台和 Codex 协议夹具之间的完整进程链路。
- 多客户端、多项目，以及对重叠活动项目的限制。
- 客户端被终止后任务继续运行，以及重新连接。
- 后台突然退出后的恢复、持久历史和过期审批拒绝。
- 完成、失败、中断、不确定等状态，以及确认丢失后不重放操作。
- 动态模型/推理强度校验、持久后续对话和模型切换。
- 父代理问题、原生问题、非阻塞问题、人工同意、拒绝、受限选项及操作者启用的转发。
- MCP 表单确认、关闭界面后不授予权限，以及不支持确认界面时的替代路径。
- 文件补丁审核上下文、项目外文件授权拒绝、权限子集/单轮范围、秘密答案拒绝及未知请求拒绝。
- 持久事件分页、按字节预算分页而不丢记录、原始推理过滤和认证/令牌脱敏。
- 路径越界、符号链接、项目目录被替换、私有通信权限，以及不开放任意原始 API。
- 取消轮询而不中断任务、可选进度通知、迟到的界面响应处理。
- 原生审核器与设置变更、模型档位、计划模式、子代理/后代所属关系及重启后的订阅恢复。
- 分叉、重命名、归档/恢复/删除，对活动任务或越界后代的拒绝，以及队列、审查、压缩和历史回退。
- 明确的目标意图、不隐式添加预算、限定范围的原生会话导入、技能选择，以及文件/图片输入和不可变图片快照。

开发执行环境的外层限制阻止未经许可的 Unix 套接字创建，初次 IPC 测试因此失败。在获准使用私有本地套接字的执行环境中重跑后通过。应用本身没有关闭自身或 Codex 的安全控制。

## 真实 Codex 检查

这些脚本需要主动选择运行，会消耗真实账户用量，必须使用**可丢弃项目**。`live_smoke.py` 要求项目为空；脚本把 JSON 结果保存在私有状态目录。

```bash
python3 scripts/live_smoke.py --config /absolute/disposable-config.toml --workdir /absolute/disposable-project
python3 scripts/live_controls.py --config /absolute/disposable-config.toml --workdir /absolute/disposable-project
```

| 真实检查 | 观察到的结果 |
|---|---|
| app-server 初始化及原生账户访问 | 通过，仅公开认证类型和状态 |
| 模型和推理强度发现 | 使用安装账户的模型目录，通过 |
| 命名读写权限及准确项目目录确认 | 通过 |
| Codex 调用 `ask_parent` 并收到主代理回答 | 通过 |
| 编程任务 | 创建 `calculator.py` 的 `add(a, b)` 与 `test_calculator.py` |
| 实际项目测试 | `python3 -m unittest -v`，**3 项通过**，退出码 0 |
| 持久后续对话 | 在同一原生线程中，根据先前对话描述函数和用例 |
| 后台关闭、重启、恢复 | 通过，历史返回两个轮次 |
| 运行中引导 | 控制测试的 sleep 命令运行期间接受引导 |
| 中断 | 原生 `turn/completed` 确认 `interrupted` |
| 项目外读取 | 沙箱中的 `cat` 无法读取项目外的合成标记文件，内容未进入事件 |

初始受限配置没有允许读取主目录下的独立 Codex 可执行文件，导致 bubblewrap 报告找不到程序。实现随后只允许读取该**准确的二进制文件**，真实编程检查通过；没有放开整个主目录，也没有批准沙箱外重试。初次审批还表明，`availableDecisions` 可能没有 `decline`；此时测试选择提供的 `cancel` 来拒绝。

真实编程检查还发现最小运行环境中没有 `rg`。Codex 改用系统目录工具，完成实现和三个 Python 测试。该命令失败被保留为工具链访问限制，没有被描述成成功。需要时可配置具体的只读工具链路径。

## 扩展控制的早期真实检查

以下脚本会各自创建临时项目/配置/状态，并消耗账户用量：

```bash
python3 scripts/live_extended.py
python3 scripts/live_child_approval.py
```

扩展检查通过了原生子代理发现/订阅、父任务事件汇总、明确选择 `auto_review` 和接收原生审核结果。审核器批准了无害的 `printf AUTO_REVIEW_OK` 提权测试，沙箱和审核控制仍然启用，桥接没有伪造审批响应。

同一次检查还通过了原生计划/审核器变更、分叉和重命名、队列添加/读取/消费、暂停目标的设置/读取/清除、能力/技能/后台终端/额度读取、代码审查、压缩、历史回退，以及自身临时分叉的归档/恢复/删除。没有删除用户已有会话或项目。队列更新/删除/排序及进程停止由夹具测试覆盖；真实空闲队列曾先于更新消费条目，因此加入了明确的竞争情况处理。

单独的原生恢复检查在后台重启和权限配置版本变化后重新打开父子会话，确认子任务 ID 和订阅保持一致，且未启动新模型轮次。

夹具还发现了关闭时的竞争：有序事件处理器正在排空时取消，可能跳过已加载会话的失效清理。清理已放入 `finally`，对应断连/恢复回归检查通过。

真实子代理审批检查中，子代理请求出现在父任务轮询里；主代理提交可用的取消决定；Codex 将命令记录为拒绝，并中断子轮次。没有授予权限。取消后父代理可能继续等待，测试明确中断父代理，再发送后续说明，而不是重启被拒绝的操作，之后父代理完成报告。这个原生等待边界和恢复路径已经写入示例。

同一检查确认了真实图片和文本输入：Codex 识别出来自私有快照的蓝色合成图片，并复述项目 UTF-8 引用文件的标记。初次检查因父代理持续等待而超时；补上明确的父代理恢复流程后通过。
