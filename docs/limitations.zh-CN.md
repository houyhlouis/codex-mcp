# 已知限制与替代方案

[English](limitations.md) | 简体中文 · [中文首页](../README.zh-CN.md)

以下是当前实现的边界，不代表底层平台永远无法支持更多功能。方案调查比较了直接 app-server、两种官方 SDK、批处理 CLI、本地 daemon/proxy 和原生终端交互，详见 [集成方案调查](integration-research.zh-CN.md)。

| 限制 | 已调查的方式及原因 | 合规的部分方案 |
|---|---|---|
| 并非所有主代理都会自动显示通知 | 客户端的进度通知和人工确认能力不同，发送通知不能强制客户端显示或处理它。 | 通过有时限的轮询读取全部已记录事件，待处理请求独立返回；支持时再使用进度令牌和表单确认。 |
| 后台/Codex 崩溃后不能保证恢复每个流式增量 | 直接 stdio 没有上游事件重放游标；原生历史能恢复持久化轮次和条目，不一定包含瞬时增量。共享 daemon 也需要明确的订阅/重放机制。 | SQLite 保留已经提交的接收事件；重启标记可能的缺口，恢复后分页读取原生历史，不自动重试输入或 Shell 操作。 |
| 丢失控制确认时，无法跨故障保证恰好执行一次 | Codex 可能已经接受操作，但进程在响应持久化前失败。应用层幂等键不能事后把上游操作变为事务。 | 保存操作键和不确定结果，提供任务 ID，并核对线程历史；检查后再决定是否发送新指令。 |
| 人工审批需要界面或显式受信任转发 | 客户端不一定支持 elicitation；参数里声称已获同意不是独立证据，包装层也无法隔离同用户无限制 Shell。 | 原生 `approve_for_me` 已实现并测试适用的自动审核；仍需人工处理时可用 MCP 界面、终端或显式可信转发。 |
| 桥接只开放单次审批范围 | schema 还提供会话级同意和规则修订，这些技术上可实现，但会扩大后续权限或改变持久策略，因此未开放。 | 在桥接内逐次审批；更宽策略应在原生 Codex 中有意审阅和设置。 |
| 秘密问题及高级外部表单 | 原生 schema 可包含秘密字段、URL 流程及复杂 JSON Schema；经模型可见参数传递秘密有泄露风险，小型校验器也拒绝不支持的结构。 | 使用原生登录或提供商浏览器流程，在支持时只转发完成结果。简单表单和普通问题已实现；未来秘密通道必须避开模型可见内容及历史回显。 |
| 命名权限和动态父代理工具使用实验字段 | 安装版本对这些字段要求实验能力。回退到普通 workspace-write 会失去读取限制，文本/PTY 解析会失去明确的请求关联。 | 最低要求 Codex 0.167.0，验证原生确认结果，按已安装 schema 检查，并在不兼容时拒绝运行。未来缺少父代理工具时，可在适配和验证后采用普通后续文本。 |
| 系统目录外的部分工具链需要配置 | 严格读取范围曾使主目录中的独立 Codex 可执行文件不可见，而放开整个主目录会暴露其他项目和凭据。 | 默认允许准确的 Codex 可执行文件；通过操作者审阅的 `toolchain_paths` 添加具体只读运行时/依赖目录。标准 Python 编程和测试已实测。 |
| 更广的原生账户历史仍受限制 | 原生线程接口可以访问比选定项目更广的历史；任意线程 ID 会削弱所属关系检查。 | 支持工作目录完全匹配的明确会话发现/导入，并要求确认其他客户端已停止；验证通过的后代也支持，无关会话不开放。 |
| 没有 Git worktree 自动管理 | 已有 worktree 可当作普通项目目录；创建/移动还涉及 Git 修改及未整理工作区语义。 | 选择已有的独立 worktree；不同目录中的并行任务可用。项目创建只创建目录。 |
| 没有原生终端 UI 或无限制 Shell/PTY 透传 | `thread/shellCommand` 在沙箱外运行，通用代理会破坏项目边界。 | 图片/文本上下文、技能、计划、审查、分叉、队列、目标和生命周期控制已实现；交互程序及应用界面功能仍使用原生终端。 |
| 只接受 MCP 2026 的客户端 | 当前 SDK 提供新生命周期及兼容回退；本实现使用既有握手协议和应用层轮询，没有采用全部新扩展。 | 使用支持旧协议回退的客户端，官方 MCP 1.26.0 已测试；原生 SDK v2 适配是后续可行方案，不是根本不可能。 |
| 平台与客户端覆盖不完整 | 开发环境提供 Linux 和真实 Codex，没有 Claude Code 界面或原生 Windows/macOS 执行环境。Windows IPC/ACL/锁和 macOS 对端/路径适配已实现，但未在本机执行。 | Linux 是本地验证过的运行平台；原生适配和 CI 作业已提供。Claude Code 配置依据官方文档，未宣称实测其 UI；WSL 也未实测。 |

未知或不支持的服务端请求返回错误，不授予权限。这也包括外部凭据刷新和 attestation 回调：桥接采用已安装 CLI 自身保存的正规认证。需要这些其他流程的部署必须另行取得授权并实现，不能靠提取凭据替代。

远程接入未开放，因为本项目要求本地运行；使用云端模型时，Codex 仍需向获得授权的模型服务发送出站请求。

[终端功能对照表](terminal-parity.zh-CN.md) 给出了完整映射。原生子代理管理和明确的 Approve for me 已经实现。禁止直接输入的原生子代理仍经父代理控制；队列项可能先于更新请求被消费，此时会报告结果，不会自动再次执行。

实测的原生运行时中，取消子代理审批会中断子代理，却可能让父代理继续等待。父任务事件轮询能够看到子代理中断，`family_status` 仍为活动状态。主代理可以明确中断等待中的父代理，再发送说明拒绝情况的后续指令。桥接不会静默重启子代理、覆盖拒绝或虚构最终回答。

项目通过 `workdir`/`project_id` 动态选择，不使用配置中的工作区根目录。详见 [配置说明](configuration.zh-CN.md)和[平台说明](platforms.zh-CN.md)。
