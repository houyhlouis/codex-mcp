# 安全与信任边界

[English](security.md) | 简体中文 · [中文首页](../README.zh-CN.md)

## 本地账户边界

这是同一用户下的本地集成，不是多用户或远程服务。MCP 使用继承的标准输入输出；后台在 Linux/macOS 上使用私有 Unix 套接字，在 Windows 上使用原生命名管道，不使用 TCP/HTTP。状态由 Unix 所有者/权限位或 Windows DACL 保护，并检查对端身份。Windows 管道拒绝远程客户端和受限令牌进程。服务不提供网络监听地址或远程控制设置。

后台只接受明确列出的工具操作、健康检查、本地人工审核响应和关闭请求。没有原始 JSON-RPC 代理或任意 Shell/文件读取工具。Codex 可执行文件从 `PATH` 发现，或由操作者在可选配置中指定；启动时使用参数数组，不把模型提示拼接成 Shell 命令。

已经具有同一操作系统用户权限的进程，本来就能够访问该用户的文件和程序。套接字权限和审核入口无法区分真正的人与完全受信任的同用户进程。这里主要防范误用、提示/工具参数注入、未经授权的路径选择和不受信任的远程调用者，不防范恶意管理员或拥有同用户无限制 Shell 的进程。

## 项目与执行

项目目录由受信任的主代理明确选择或创建，配置文件中没有工作区列表。该选择为任务授予所选项目范围内的访问。路径会检查越界、符号链接和 Windows 重解析点；过宽的根目录以及私有状态/凭据目录会被拒绝。独立活动任务组不能重叠，验证通过的原生后代可以在父项目内协作。

每个 Codex 会话使用命名权限配置，其中包括：

- 将所选项目设为唯一的运行时工作区根目录。
- 在创建任务时选择 `read` 或 `write` 项目访问。
- 允许必要的平台运行文件、准确的 Codex 可执行文件，以及操作者配置的额外只读工具链路径。
- 禁止访问桥接服务的状态目录和真实配置文件。
- 默认关闭命令网络访问，直到原生策略/审批允许某项请求的例外。

发送工作前，桥接会核对原生确认的权限配置 ID、工作目录、运行时根目录和审批策略。不会降级为完全访问、关闭沙箱、绕过钩子信任、忽略规则或修改管理员要求。不支持或被拒绝的配置会直接失败。

这些配置约束 Codex 的沙箱工具，并不是包围整个用户账户所有进程的容器。Codex 自身受信任的运行时仍需访问认证/配置及模型服务。原生可信钩子和显式启用的外部工具有各自的信任边界。模型推理、网页搜索、外部连接器的网络访问与沙箱命令的网络访问也不同。

桥接会话默认关闭外部 MCP、应用和插件。`allow_external_tools = true` 是操作者选择使用既有授权集成的开关，不会让这些集成自动服从项目文件系统沙箱。如果 Codex 的配置又指向本桥接，也可能形成递归委派。启用前应理解相关集成及其权限。

## 审批路由

Codex 仍然负责落实策略。桥接只记录请求并转发支持的响应，不能把不允许的权限配置或账户权限变成可用。

| 请求 | 默认处理方式 |
|---|---|
| `ask_parent` 上下文问题 | 主代理可直接回答 |
| 命令/文件审批 | 人工界面或终端；主代理可以拒绝/取消 |
| 附加权限 | 人工界面或终端；主代理可以不授予任何权限 |
| 原生用户问题 | 人工界面或终端，因为部分连接器审批也使用此格式 |
| 外部 MCP elicitation | 人工界面或终端；主代理可以拒绝/取消 |
| 未知请求方法 | 明确返回错误，不授予权限 |

任务可以明确选择原生 `approve_for_me`，将适用请求交给 Codex 自动审核器。对应参数为 `approvalsReviewer: "auto_review"` 和 `approvalPolicy: "on-request"`，同时保留受限项目配置。服务会在创建/恢复时核对审核器，并记录原生自动审核事件，不会伪造同意响应来模拟该模式。管理员要求仍可拒绝这个选择；任务级设置不会修改全局凭据或配置。

原生子代理的所属关系来自 app-server 元数据，而不是提示文本或模型随意提供的线程 ID。父链必须连接到已管理的任务，子代理工作目录必须位于父项目内，恢复后确认的权限配置和根目录也必须匹配。后台只订阅验证通过的子代理，并在重启后重新检查。请求保留来源子任务及父/根任务 ID；无关或越出项目的子代理不会接入。不接受直接输入的子代理仍由原生父代理控制。

只允许明确导入已停止、且工作目录与选定项目完全一致的原生根会话。调用者必须确认它已在其他客户端中停止，因为本服务无法可靠看到另一个 app-server 的活动进程。导入后，在开始新轮次前应用桥接的受限配置。归档、删除和历史回退只针对所属任务组；删除需要确认准确的原生线程 ID，历史回退要明确确认不会撤销文件。这些确认记录调用者意图，不是独立的人类操作证明。

`approval_relay = true` 允许主代理转发支持的决定，必须在模型工具之外配置并重启后台。它是信任委托，不是用户点击的证明。人工界面适配器需要明确接受的响应；默认值、超时、取消和客户端不支持都不会自动批准。

`codex_respond` 只开放单次审批，不开放 `acceptForSession`、命令规则修订、持久网络规则或会话级权限授权。文件审批会在可用时展示拟应用补丁，不能授予项目外文件访问。额外权限只能是请求的子集，并限定为项目内具体路径。原生自动审核遵循 Codex 自身策略，可批准或拒绝提权；审核通过的操作可能获得更宽的原生权限，其结果保存在公开审核记录中。没有全局无条件提权或自动推翻拒绝的模式。

待处理请求绑定到当前后台实例和任务，在断开、重启或轮次完成后失效。过期回答会被拒绝。桥接不会在 `autoResolutionMs` 到期后自动回答问题，也不会静默恢复旧授权。

## 凭据与保留的数据

桥接不打开 Codex 认证文件，不导出令牌，不切换登录或退出账户，也不实现替代认证流程。`account/read` 对外只保留登录类型和是否存在账户；身份字段和凭据不公开。正常认证及刷新仍由已安装的 Codex 进程负责。

不要把凭据放进任务提示、回答、命令输出，或主动暴露给编程代理的项目文件。桥接不接受标记为秘密的问题答案，应使用原生认证或提供商浏览器流程。服务不会代用户访问授权 URL 或取得令牌。

SQLite 日志包含提示、代码差异、进度和命令输出。保存/返回前会脱敏常见令牌、密钥模式和敏感字段，并排除原始推理内容。模式匹配无法识别任意文本中的所有秘密，因此整个状态目录及 Codex 自身历史都应按敏感本地数据处理。本应用不对它们进行加密。

引用文件通过目录描述符或对应平台机制读取，拒绝符号链接、非普通文件和超出大小限制的输入。图片从获准项目读取后复制到私有状态目录，避免校验后的可写项目路径被替换为凭据文件。快照会一直保留，直到操作者清理状态。普通上下文文本和选定技能的指令属于不受信任内容，不能据此扩大项目范围。

响应记录只保存请求 ID、类型和审核来源，不保存回答正文。Codex 后续可能在条目或历史事件中回显非秘密回答，这些事件按一般脱敏规则记录；认证秘密因此必须走专用认证渠道。

存储记录的是明确的项目选择，保存的任务路径在使用前会重新校验，旧任务目录可以迁入登记表。没有自动删除事件的功能；手动清理或备份状态前应停止后台。
